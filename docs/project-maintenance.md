# 项目投入与验收清单

更新于 2026-11-13。以下是维护方向，未勾选的内容不代表已实现或已验收。

| 项目 | 当前投入方式 | 下一次交付的验收依据 |
| --- | --- | --- |
| Agent Quality Harness | 技术代表作，优先处理协议和评测可靠性 | 可复现的 Baseline / Candidate 对比、失败回放与 Gate 决策；代码版本和数据绑定 |
| SignalForge | 业务代表作，保持研究与回测口径可核对 | 固定数据案例、输入参数、评估区间、费用与复算结果；明确数据和成交假设 |
| Interview Room | 实际使用反馈驱动，保留衍生来源 | 合成材料的准备、作答、复盘和重答流程；真实模型效果另行评估 |
| Engineering Document Review | 按部署和故障恢复证据推进 | 区分 SQLite/Fake/TXT 演示、真实 Temporal 和尚待验收的完整存储栈 |
| AgriGraph | 稳定检索、引用和防治边界 | 固定问题集及失败/降级记录；图片症状理解不包装为诊断准确率 |
| WorkPilot | 修复实际使用与长期运行问题 | 离线回归、锁文件一致性、恢复/保留策略及证据引用；不以合成测试替代模型质量 |
| LearningLoop | 收尾现有工作后再扩展 | provider 诊断、复习流程和用量记录的定向验证 |

## 下一批候选

- [ ] 逐组复核依赖 PR，先解决可复现的安装、运行或安全更新问题；大版本单独验证。
- [ ] 为技术代表作准备一条能从干净环境复现的完整演示，包含至少一个失败案例。
- [ ] 把已验收的版本、变更说明、运行步骤和限制整理成正式 Release。
- [ ] 继续熟悉项目的外部开源贡献，开工前刷新 Issue、已有 PR 和贡献规则。

每项修改走到提交、推送和远端检查。PR 可以保留审阅，合并应依据质量与范围；默认分支交付之后继续确认主分支检查。衍生项目保留许可证和来源，新增功能、测试与个人职责分别说明。
